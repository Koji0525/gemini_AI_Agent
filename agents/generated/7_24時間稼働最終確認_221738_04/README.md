# 24時間自律稼働システム最終確認 (Task ID: 7_24時間稼働最終確認_221738_04)

## 概要

本プロジェクトは、開発中の24時間自律稼働システムが本番運用可能な状態であることを最終確認するためのフレームワークを提供します。システムを無人で24時間稼働させても、メモリリーク、高CPU使用率、ディスク容量不足、エラーハンドリングの不備、APIレート制限超過などの問題が発生しないことを保証することを目的としています。

この検証フレームワークは、以下の主要な側面をカバーし、システムが安定して信頼性の高い運用を提供できることを確認します。

-   **長時間稼働安定性**: システムリソースの監視と異常検知。
-   **堅牢なエラーハンドリング**: 自己修復(F7)、リトライメカニズム、人間への通知(F9)の検証。
-   **自己進化サイクル**: 学習(F8)とナレッジ蓄積の動作確認。
-   **外部連携の監視**: 主要API（Claude, Google Sheets）の使用量とレート制限への対応確認。
-   **運用ログ管理**: ログローテーション、重要イベント記録、エラー通知の確認。
-   **運用チェックリスト**: 起動前、稼働中、停止時に必要な具体的な確認項目の提供。

提供されるPythonスクリプトは、これらの検証ステップをシミュレートし、システムの「sh/run_autonomous_24h_v3.sh」スクリプトの出力や「logs/」ディレクトリのファイルを分析（シミュレート）して、最終的な評価レポートを生成します。

## インストール

このプロジェクトはPython 3.8以上を必要とします。
特に外部ライブラリは使用していませんが、もし追加のリアルタイム監視が必要な場合は `psutil` などのインストールが必要になる場合があります。

1.  **Python環境の準備**:
    Python 3.8+ がインストールされていることを確認してください。

2.  **プロジェクトのクローンまたはファイルのダウンロード**:
    ```bash
    git clone <リポジトリURL>
    cd <プロジェクトディレクトリ>
    ```
    または、`main.py`, `utils.py`, `README.md` を適切なディレクトリに配置してください。

3.  **依存関係のインストール (現在不要ですが、将来の拡張のために)**:
    ```bash
    # 必要に応じて、例えばリアルタイム監視ライブラリなどをインストール
    # pip install psutil
    ```

## 使用方法

本検証フレームワークは、`main.py` スクリプトを実行することで起動します。
これは、指定されたテスト期間（デフォルトでは短時間でシミュレーション）にわたって、様々なシステムコンポーネントの動作をシミュレートし、その結果を評価します。

1.  **ログディレクトリの準備**:
    スクリプトは自動的に `logs/` ディレクトリを作成し、その中に全てのシミュレーションログと最終レポートを出力します。

2.  **検証の実行**:
    ```bash
    python main.py
    ```

3.  **テスト期間の調整**:
    `main.py` 内の `AutonomousSystemVerifier` クラスのインスタンス化時に `test_duration_hours` パラメータを変更することで、長時間稼働テストのシミュレーション期間を調整できます。
    デフォルトはテストを迅速に完了させるために `0.1` 時間（6分）に設定されています。本番環境に近い確認を行う場合は、より長い時間（例: `6.0` 時間）に設定してください。

    ```python
    # main.py の一部
    verifier = AutonomousSystemVerifier(log_dir="logs", test_duration_hours=0.1) # 6分間のシミュレーション
    # または
    # verifier = AutonomousSystemVerifier(log_dir="logs", test_duration_hours=6.0) # 6時間以上のシミュレーション
    ```

4.  **結果の確認**:
    実行後、`logs/` ディレクトリ内に生成された `verification_report_YYYYMMDD_HHMMSS.txt` ファイルを確認してください。このレポートには、各検証ステップの詳細な結果と最終的なステータス、そして作成されたチェックリストが含まれています。
    また、各ステップで生成された詳細なシミュレーションログも同ディレクトリ内に保存されます。

## API仕様

このプロジェクトは、既存の自律稼働システムの検証ツールであり、外部から呼び出されるAPIを提供しません。
内部的には、以下の外部サービスAPIの使用を監視することを目的としています。

-   **Claude API**: 大規模言語モデルの利用状況を監視し、レート制限への対処を確認します。
-   **Google Sheets API**: データ永続化やレポート生成に使用されるGoogle Sheets APIの利用状況を監視し、レート制限への対処を確認します。

`utils.py` 内の `track_api_usage` 関数は、これらのAPIの使用量とレート制限ヒットをシミュレートします。実際の実装では、各APIのクライアントライブラリや専用の監視ツールを統合して、リアルタイムの使用データを取得・分析する必要があります。

## 検証ステップの詳細

タスク説明にある各ステップは、`main.py` の `AutonomousSystemVerifier` クラス内でメソッドとして実装され、`utils.py` のヘルパー関数を利用してシミュレートされます。

1.  **長時間稼働テスト**:
    -   `sh/run_autonomous_24h_v3.sh` の実行を想定し、CPU、メモリ、ディスク使用量をシミュレートして異常がないかを確認します。
    -   メモリリーク、高CPU使用率、ディスク容量不足の兆候を検知します。
2.  **エラーハンドリングの検証**:
    -   F7 (自己修復) が正常に動作するかをシミュレート。
    -   F7で解決しない場合の最大3回のリトライ処理をシミュレート。
    -   最終的に解決できないエラーの場合、F9 (人間通知) が発火するプロセスをシミュレート。
3.  **学習サイクルの動作確認**:
    -   F8 (自己進化) がトリガーされる条件（6時間稼働/50エラーなど）をシミュレートし、トリガーされることを確認。
    -   ナレッジベースへの蓄積とパターン学習の効果をシミュレートし、継続性と有効性を確認。
4.  **API使用量の監視**:
    -   Claude APIとGoogle Sheets APIのダミー使用量を生成し、設定されたレート制限を超過しないかを検証。
    -   レート制限に近づいた、または到達した場合のシステムの対処をシミュレート。
5.  **ログ管理の確認**:
    -   ログファイルのローテーションが正しく機能するかをシミュレート。
    -   重要なシステムイベントや警告がログに記録されることを確認。
    -   エラーログから適切な通知がトリガーされることをシミュレート。
6.  **最終チェックリストの作成**:
    -   システムを起動する前、稼働中、停止時に確認すべき具体的な項目をリストアップし、レポートに含めます。

## 成功基準

この検証フレームワークの実行が以下の基準を満たした場合、システムは本番運用可能と判断されます。

-   **6時間以上の連続稼働が成功する**: 長時間稼働テストでリソース異常が検出されないこと。
-   **エラー時の自動修復が正常に動作する**: F7とリトライメカニズムが期待通りに機能し、問題を解決できること。
-   **学習サイクルが自動実行される**: F8のトリガー条件が満たされ、ナレッジ蓄積とパターン学習が継続していること。
-   **API使用量が許容範囲内に収まる**: 主要APIがレート制限に到達せず、健全な使用状況にあること。
-   **詳細なチェックリストが作成される**: 運用に必要な起動前、稼働中、停止時のチェックリストが網羅的に提供されること。
-   **ログ管理が適切に機能する**: ログローテーション、重要イベント記録、エラー通知が全て検証されること。
