# 24時間自律稼働システム 統合テストスイート

## 概要

このプロジェクトは、24時間自律稼働システムの主要機能であるF1（ゴール分解）からF10（健全性チェック）までの統合テストを実行するためのフレームワークです。システムの全機能が正しく連携し、期待通りに動作することを保証することを目的としています。
`main.py`スクリプトは、各機能の初期化、基本的な動作、および相互連携をシミュレートし、ナレッジシステム（F4）の読み書き、Google Sheets連携の動作確認を含めた包括的なテストを実施します。テスト結果は詳細なレポートとして出力され、システムの健全性を一目で把握できるように設計されています。

**【タスクID】** 7_統合テスト実行_032337_01

**【タスク説明】** F1-F10の統合テストを実行し、全機能が正常に動作することを確認する。

**【目的】** 24時間自律稼働システムの全機能が正しく連携し、期待通りに動作することを保証する。システムの各コンポーネントが孤立して機能するだけでなく、それらが統合された際に全体として安定した挙動を示すことを確認します。これにより、予期せぬ連携エラーやボトルネックを早期に特定し、システムの信頼性とロバスト性を向上させます。

**【作業内容】**
1.  **`tests/system_protection/test_core_functions.py` の実行**: (注: このテストスイートは、提供された指示に基づき、`main.py` 内でF1-F10の統合テストロジックとして実装されています。実際のファイルパスではなく、そのロジックをこのフレームワークが担当します。)
2.  **F1（ゴール分解）からF10（健全性チェック）まで全機能をテスト**:
    *   **F1: GoalDecomposition (ゴール分解)** - 複雑なゴールを管理可能なタスクに分解する機能。
    *   **F2: PlanningEngine (計画)** - 分解されたタスクを実行計画に編成する機能。
    *   **F3: ExecutionEngine (実行)** - 計画されたタスクを実際に実行する機能。
    *   **F4: KnowledgeSystem (ナレッジシステム)** - システムが学習した情報や設定を一元管理する機能。
    *   **F5: MonitoringSystem (監視)** - システムの状態、パフォーマンス、外部環境をリアルタイムで監視する機能。
    *   **F6: EvaluationModule (評価)** - 実行結果や監視データを基にシステムのパフォーマンスを評価する機能。
    *   **F7: AdaptationEngine (適応)** - 評価結果に基づいてシステムの挙動や設定を自動調整する機能。
    *   **F8: SelfHealingSystem (自己修復)** - システム内の異常や障害を検出し、自動的に修復を試みる機能。
    *   **F9: SecurityModule (セキュリティ)** - システムのセキュリティを確保し、潜在的な脅威から保護する機能。
    *   **F10: HealthCheckSystem (健全性チェック)** - システム全体の健全性を定期的にチェックし、レポートする機能。
3.  **各機能の存在確認、初期化確認、基本動作確認を実施**: 各機能モックが正しくインスタンス化され、初期化メソッドが呼び出され、基本的な入出力処理が期待通りに動作するかを検証します。
4.  **ナレッジシステム（F4）の読み書きテスト**: ナレッジシステムへのデータの書き込みと読み出しが正確に行われるかを確認し、データの永続性と一貫性を保証します。
5.  **Google Sheets連携の動作確認**: 外部システム（Google Sheets）とのデータ同期機能が正常に動作し、データの送受信が正しく行われるかをシミュレートを通じて検証します。

**【成功基準】**
*   **全テストで85%以上の成功率を達成**: 実行された全てのテストケースのうち、85%以上が成功することを目標とします。
*   **F1-F10の全機能が正常に初期化される**: 全てのコアシステム機能がエラーなく起動し、利用可能な状態になることを確認します。
*   **ナレッジシステムが正常に動作する**: F4のナレッジシステムが、データの読み書き操作において一貫性と信頼性を示すことを確認します。
*   **テスト結果レポートが生成される**: 実行されたテストのサマリー、詳細、成功基準の達成状況を含むマークダウン形式のレポートファイルが自動的に生成されること。

**【コンテキスト】**
この統合テストスイートは、システムの「保護テストスイート」の一部として位置づけられます。各機能の最新実装状態を反映したモックアップを使用しており、現実のシステムコンポーネントがまだ開発段階であっても、そのインターフェースと期待される動作をシミュレートすることで、早期の統合問題発見と品質保証を可能にします。システム全体の堅牢性と信頼性を高めるための重要なステップです。

## インストール

このプロジェクトはPython 3.8+ で動作します。
特に必要な外部ライブラリはありませんが、Pythonの標準ライブラリのみを使用しています。

1.  **Pythonのインストール**:
    お使いのシステムにPython 3.8以上がインストールされていることを確認してください。
    ```bash
    python --version
    # または
    python3 --version
    ```
    もしインストールされていない場合は、[Python公式サイト](https://www.python.org/downloads/) からダウンロードしてインストールしてください。

2.  **プロジェクトのクローン (任意)**:
    もしこのコードがリポジトリにある場合、以下のようにクローンできます。
    ```bash
    git clone <repository_url>
    cd <project_directory>
    ```

## 使用方法

統合テストを実行するには、`main.py`スクリプトを直接実行します。

```bash
python main.py
```

### テスト実行後の出力

1.  **コンソール出力**: テストの進行状況と結果の概要がリアルタイムでコンソールに表示されます。
2.  **ログファイル**: `integration_test_log.log` というファイルに、詳細なログ（DEBUG, INFO, ERRORレベル）が記録されます。問題発生時のデバッグに役立ちます。
3.  **テスト結果レポート**: `test_results/integration_test_report_YYYYMMDD_HHMMSS.md` という形式で、マークダウン形式のレポートファイルが生成されます。このレポートには、テストサマリー、各テストケースの詳細な結果、成功基準の達成状況が含まれます。

### レポートの解釈

生成されるマークダウンレポートは以下のセクションで構成されます。

*   **テストサマリー**: 合計テスト数、成功数、失敗数、成功率の概要。
*   **テスト詳細**: 各テストケースのステータス（✅ 成功 / ❌ 失敗）、テスト名、および実行結果メッセージのリスト。
*   **失敗したテスト**: 失敗したテストケースが一覧表示され、原因特定に役立ちます。
*   **成功基準の確認**: プロジェクトの成功基準（85%成功率、初期化成功、ナレッジシステム動作、レポート生成）がそれぞれ達成されたかどうかが明示されます。

このレポートをレビューすることで、システムの統合状態と健全性を迅速に評価できます。

## API仕様 (内部テスト対象機能のモック)

このテストフレームワークは、以下の主要機能のモックアップと連携をテストします。これらは、`main.py`で`BaseSystemFunction`を継承したクラスとして定義されています。

### F1: GoalDecomposition
-   `initialize()`: ゴール分解機能を初期化します。
-   `decompose_goal(goal: str) -> Tuple[bool, List[str]]`: 指定されたゴールをサブタスクリストに分解する処理をシミュレートします。

### F2: PlanningEngine
-   `initialize()`: 計画機能を初期化します。
-   `generate_plan(tasks: List[str]) -> Tuple[bool, Dict[str, Any]]`: タスクリストに基づいて実行計画を生成する処理をシミュレートします。

### F3: ExecutionEngine
-   `initialize()`: 実行機能を初期化します。
-   `execute_plan(plan: Dict[str, Any]) -> Tuple[bool, str]`: 生成された計画を実行する処理をシミュレートします。

### F4: KnowledgeSystem
-   `initialize()`: ナレッジシステムを初期化します。
-   `write_knowledge(key: str, value: Any) -> Tuple[bool, str]`: 指定されたキーと値で知識を書き込む処理をシミュレートします。
-   `read_knowledge(key: str) -> Tuple[bool, Any]`: 指定されたキーの知識を読み出す処理をシミュレートします。

### F5: MonitoringSystem
-   `initialize()`: 監視システムを初期化します。
-   `monitor_status(entity_id: str) -> Tuple[bool, Dict[str, Any]]`: 特定のエンティティの状態を監視する処理をシミュレートします。

### F6: EvaluationModule
-   `initialize()`: 評価モジュールを初期化します。
-   `evaluate_performance(metrics: Dict[str, Any]) -> Tuple[bool, str]`: 与えられたメトリクスに基づいてパフォーマンスを評価する処理をシミュレートします。

### F7: AdaptationEngine
-   `initialize()`: 適応エンジンを初期化します。
-   `adapt_system(recommendation: str) -> Tuple[bool, str]`: 推奨事項に基づいてシステムを適応させる処理をシミュレートします。

### F8: SelfHealingSystem
-   `initialize()`: 自己修復システムを初期化します。
-   `detect_and_heal(issue_description: str) -> Tuple[bool, str]`: 特定の課題を検出し、修復を試みる処理をシミュレートします。

### F9: SecurityModule
-   `initialize()`: セキュリティモジュールを初期化します。
-   `run_security_scan(target: str) -> Tuple[bool, str]`: 指定されたターゲットに対してセキュリティスキャンを実行する処理をシミュレートします。

### F10: HealthCheckSystem
-   `initialize()`: 健全性チェックシステムを初期化します。
-   `perform_system_health_check() -> Tuple[bool, str]`: システム全体の健全性チェックを実行する処理をシミュレートします。

### GoogleSheetsIntegration (特殊機能)
-   `initialize()`: Google Sheets連携機能を初期化します。
-   `sync_data(data: List[Dict[str, Any]]) -> Tuple[bool, str]`: 指定されたデータをGoogle Sheetsに同期する処理をシミュレートします。
-   `get_mock_data() -> List[Dict[str, Any]]`: モックとして保存されたデータを取得します。

これらのモックは、実際のシステムが未完成の場合でも、統合テストのシナリオを網羅し、コンポーネント間のインターフェースと期待される動作を検証するための基盤を提供します。
