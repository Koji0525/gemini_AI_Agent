# 24時間自律稼働システム 統合テストスイート

## 概要
このリポジトリは、24時間自律稼働システムの中核機能であるF1（ゴール分解）からF10（健全性チェック）までの統合テストを目的としたテストスイートです。システムの全機能が正しく連携し、期待通りに動作することを保証するために設計されています。

このテストスイートは以下の主要な目的を達成します。
1.  **機能連携の検証**: F1からF10までの各機能モジュールが相互に連携し、一貫した動作を提供することを確認します。
2.  **基本動作の保証**: 各機能の存在確認、初期化、および最も基本的な操作が正常に実行されることを検証します。
3.  **ナレッジシステムとの統合**: システムの中核データストアであるナレッジシステム（F4）の読み書き操作の信頼性をテストします。
4.  **外部サービス連携の確認**: Google Sheetsなどの外部サービスとのデータ連携が正しく機能することを確認します。
5.  **システム保護とレジリエンス**: 継続的なシステム稼働を支える健全性チェック、異常検知、自己修復機能などが期待通りに動作するかを検証します。
6.  **テスト結果の可視化**: テストの成功率、失敗の詳細を含む包括的なレポートを生成し、システムの健全性に関する明確なフィードバックを提供します。

このテストスイートは、システムの継続的な開発とデプロイメントサイクルにおいて、変更が全体に与える影響を迅速に評価し、高い品質と安定性を維持するための基盤となります。

## プロジェクト構造

```
.
├── main.py                 # メインの統合テスト実行ロジック
├── utils.py                # テスト補助関数、レポート生成、安定性分析、設定検証など
├── test_results/           # 生成されるテストレポートの出力ディレクトリ
└── README.md               # この説明ファイル
```

## 機能（F1-F10）概要

*   **F1: ゴール分解 (Goal Decomposition)**: 高レベルの目標を達成可能な具体的なタスクに分解する機能。
*   **F2: 計画生成 (Plan Generation)**: 分解されたタスクに基づいて実行計画を策定する機能。
*   **F3: タスク実行 (Task Execution)**: 策定された計画に従ってタスクを実行する機能。
*   **F4: ナレッジシステム (Knowledge System)**: システムが収集・生成した知識を保存し、アクセスするためのデータベース機能。
*   **F5: モニタリング (Monitoring)**: システムのパフォーマンス、状態、外部環境を継続的に監視する機能。
*   **F6: 異常検知 (Anomaly Detection)**: モニタリングデータから異常なパターンや挙動を識別する機能。
*   **F7: 自己修復 (Self-Healing)**: 検出された異常に対して自動的に修復措置を講じる機能。
*   **F8: レポート・ロギング (Reporting & Logging)**: システムの活動、イベント、エラーを記録し、レポートを生成する機能。
*   **F9: ユーザーインタラクション (User Interaction)**: ユーザーからの入力受付や情報提供を行うためのインターフェース機能。
*   **F10: 健全性チェック (Health Check)**: システム全体の稼働状態とコンポーネントの健全性を定期的に確認する機能。

## インストール

1.  **リポジトリのクローン**:
    ```bash
    git clone https://github.com/your-repo/autonomous-system-integration-tests.git
    cd autonomous-system-integration-tests
    ```

2.  **Python環境の準備**:
    Python 3.8以上が推奨されます。仮想環境の利用を強く推奨します。
    ```bash
    python -m venv venv
    source venv/bin/activate  # macOS/Linux
    # venv\Scripts\activate   # Windows
    ```

3.  **依存関係のインストール**:
    このテストスイートは標準ライブラリと、必要に応じてテストのためのモックライブラリを使用します。
    現時点では、外部依存関係は最小限ですが、将来的に増える可能性があります。
    ```bash
    # 例: pip install requests pandas  # 実際のシステムによっては追加のライブラリが必要になる場合があります
    ```

## 使用方法

統合テストを実行するには、`main.py`スクリプトを直接実行します。

```bash
python main.py
```

実行後、`test_results/`ディレクトリに、タイムスタンプ付きのMarkdown形式のレポートファイルが生成されます。
このレポートには、各テストの成功/失敗ステータス、メッセージ、および全体的な成功率が含まれます。

### テストのカスタマイズ

*   `main.py`内の`SystemIntegrationTester`クラスで、`_run_test`メソッドや個々の`test_fX_...`メソッド内のロジックを調整して、より現実的なシミュレーションや実際のコンポーネントとの連携を実装できます。
*   `_test_function_existence_and_init`および`_test_function_basic_operation`メソッドのランダムな成功/失敗ロジックは、実際のシステムがデプロイされた際には具体的なAPI呼び出しや機能テストに置き換える必要があります。
*   `MockKnowledgeSystem`や`MockGoogleSheetsAPI`は、実際の外部サービス連携が利用可能になった際に、本物のAPIクライアントに置き換えることができます。

## レポートの解釈

`test_results/`ディレクトリに生成されるレポートファイル（例: `integration_test_report_YYYYMMDD_HHMMSS.md`）には、以下の情報が含まれます。

*   **概要**: 総テスト項目数、成功数、失敗数、全体成功率。
*   **個別テスト結果**: 各機能（F1-F10、ナレッジシステム、Google Sheets連携）ごとのサブテストの詳細な結果（成功/失敗、メッセージ）。
*   **成功基準達成度**: タスクの成功基準（85%以上の成功率、全機能の初期化、ナレッジシステムの動作、レポート生成）が達成されたかどうかが明示されます。

## エラーハンドリング

テスト実行中に発生した例外はキャッチされ、テスト結果として記録されます。これにより、どのテストステップでどのような種類のエラーが発生したかを明確に特定できます。
`utils.py`には、汎用的なロギング機能や設定検証機能が含まれており、システムの運用段階でのデバッグや問題特定に役立つでしょう。

## 拡張性

*   **新しい機能の追加**: 新しいFxx機能が追加された場合、`SystemIntegrationTester`クラスに新しい`test_fXX_new_function`メソッドを追加し、`execute_all_tests`メソッドの`test_methods`リストにそのメソッドを追加します。
*   **詳細なサブテスト**: 各機能のテストメソッド内（例: `test_f1_goal_decomposition`）に、より多くのサブテストロジックやアサーションを追加することで、テストの粒度を高めることができます。
*   **テストデータの管理**: 複雑なシナリオに対応するため、テストデータを外部ファイル（JSON, CSVなど）からロードするメカニズムを導入できます。
*   **CI/CDとの連携**: このテストスイートは、Jenkins, GitHub Actions, GitLab CIなどの継続的インテグレーション/デリバリー (CI/CD) パイプラインに容易に組み込むことができます。自動化されたテスト実行により、コード変更がシステム全体に与える影響を早期に検出し、迅速なフィードバックサイクルを確立します。
*   **フレークテスト検出**: `main.py`に`FlakkyTestDetector`クラスのスケルトンが含まれています。テスト結果履歴を蓄積することで、不安定なテストを特定し、その原因分析に役立てることができます。これはシステムの長期的な安定性向上に不可欠です。

## API仕様 (テストフレームワークとして)

このテストスイート自体はアプリケーションのAPIとして提供されるものではありませんが、内部的に以下のような主要なクラスや関数で構成されています。

*   **`main.py`**:
    *   `class TestResult`: 単一のテスト結果をカプセル化するデータ構造。
    *   `class SystemIntegrationTester`:
        *   `__init__(self, output_dir: str = "test_results")`: テスターを初期化し、結果出力ディレクトリを設定します。
        *   `_run_test(self, test_name: str, test_func: callable, *args, **kwargs) -> bool`: テスト関数を実行し、結果を記録する内部ヘルパー。
        *   `test_fX_...(self) -> bool`: 各F機能の統合テストメソッド。
        *   `test_knowledge_system(self) -> bool`: F4ナレッジシステムの読み書きテスト。
        *   `test_google_sheets_integration(self) -> bool`: Google Sheets連携テスト。
        *   `execute_all_tests(self)`: 定義された全ての統合テストを実行し、レポートを生成します。
        *   `_generate_report(self)`: テスト結果を集計し、Markdown形式のレポートファイルを生成します。
    *   `class FlakkyTestDetector`: (将来的な機能) テスト結果履歴から不安定なテストを検出する。

*   **`utils.py`**:
    *   `generate_detailed_report(results: List[TestResult], output_dir: str = "test_results") -> str`: テスト結果リストから詳細なレポートを生成するユーティリティ。
    *   `analyze_test_stability(historical_results: Dict[str, List[bool]]) -> Dict[str, Dict[str, Any]]`: 過去のテスト結果から各テストの安定性を分析する。
    *   `validate_configuration(config_path: str) -> Tuple[bool, str]`: 設定ファイルの整合性を検証する。
    *   `log_event(level: str, message: str, log_file: str = "system_logs.log")`: システムイベントをログファイルに記録する。

これらのコンポーネントは、システムの統合テストの実行、結果分析、および報告プロセスを体系的に管理するために連携して動作します。
