# Autonomous System Pre-Production Validator

## 概要
このプロジェクトは、24時間自律稼働システムが本番運用に耐えうる状態であるかを最終確認するためのバリデーターツールです。システムの長時間稼働における安定性、エラーハンドリングの信頼性、自己学習サイクルの有効性、API使用量の管理、およびログ管理の健全性を包括的に検証することを目的としています。既存のシステムログを分析し、必要に応じてリアルタイムのスナップショットを取得することで、システムが【目的】システムを24時間無人で稼働させても問題が発生しないことを保証する、という目標を達成するための最終的な評価を提供します。

### 検証項目
1.  **長時間稼働テストの分析**: システムが6時間以上の連続稼働を安定して行えるか、過去のログからメモリリーク、CPU使用率の異常、ディスク容量の逼迫がないかを分析します。また、現在のシステムリソースの健全性も確認します。
2.  **エラーハンドリングの検証**: F7（自己修復）、最大3回のリトライ、F9（人間通知）といったエラー応答メカニズムが、過去のエラーイベントログに対して適切に機能しているかを検証します。
3.  **学習サイクルの動作確認**: F8（自己進化）のトリガー条件（例: 6時間稼働または50エラー発生）が満たされた際に、学習サイクルが開始され、ナレッジ蓄積やパターン学習が継続的に行われているかをログから確認します。
4.  **API使用量の監視**: Claude APIやGoogle Sheets APIなどの外部APIの使用量を集計し、設定されたレート制限やコストの許容範囲内に収まっているかを検証します。過去のログからレート制限違反の兆候がないかも確認します。
5.  **ログ管理の確認**: ログファイルのローテーションが適切に行われているか、重要なイベントが正確に記録されているか、エラーログが適切に通知されているかを確認します。これにより、問題発生時のトレーサビリティを保証します。
6.  **最終チェックリストの提供**: 起動前、稼働中、停止時にシステム運用者が確認すべき詳細なチェックリストを提供し、本番運用の準備を万全にします。

## インストール

このバリデーターツールを実行するために必要な手順は以下の通りです。

1.  **Pythonのインストール**: Python 3.8以上のバージョンが必要です。
    ```bash
    sudo apt update
    sudo apt install python3 python3-pip
    ```

2.  **依存ライブラリのインストール**:
    ```bash
    pip install psutil
    ```
    *`psutil`はシステムのリソース（CPU、メモリ、ディスク）をリアルタイムで取得するために使用されます。*

3.  **プロジェクトのクローンまたはダウンロード**:
    このリポジトリをダウンロードし、任意のディレクトリに展開します。

## 使用方法

### 1. 設定ファイルの準備
`config.json`ファイルをプロジェクトのルートディレクトリに配置し、システムの環境に合わせて設定を調整してください。
**`config.json`の例:**
```json
{
    "log_directory": "logs/",                       // 監視対象システムのログファイルが格納されているディレクトリ
    "system_log_prefix": "system_",                 // システムリソースログのファイル名プレフィックス (例: system_YYYY-MM-DD.log)
    "error_log_prefix": "error_",                   // エラーイベントログのファイル名プレフィックス
    "learning_log_prefix": "learning_",             // 学習サイクルログのファイル名プレフィックス
    "api_log_prefix": "api_",                       // API使用量ログのファイル名プレフィックス
    "cpu_threshold_percent": 80,                    // CPU使用率の警告閾値 (%)
    "memory_threshold_percent": 90,                 // メモリ使用率の警告閾値 (%)
    "disk_threshold_percent": 95,                   // ディスク使用率の警告閾値 (%)
    "long_run_test_duration_hours": 6,              // 連続稼働テストと見なす最低時間 (H)
    "f8_error_count_threshold": 50,                 // F8トリガーのエラー数閾値 (参考値, ログから確認)
    "f8_time_threshold_hours": 6,                   // F8トリガーの時間閾値 (参考値, ログから確認)
    "max_api_calls_claude_daily": 100000,           // Claude APIの一日あたりの最大トークン数 (推定)
    "max_api_calls_g_sheets_daily": 50000,          // Google Sheets APIの一日あたりの最大リクエスト数 (推定)
    "log_retention_days": 7,                        // ログファイルの保持期間 (日) - ログローテーションチェック用
    "critical_log_patterns": [                      // ログ内で監視すべき重大なイベントパターン (正規表現可)
        "CRITICAL", "FATAL", "FAILURE", "OUT_OF_MEMORY", "EMERGENCY_SHUTDOWN"
    ],
    "error_notification_patterns": [                // エラー通知が発火したことを示すログパターン
        "ERROR_NOTIFICATION_SENT", "ALERT_TRIGGERED", "EMAIL_SENT_F9"
    ]
}
```

### 2. ログファイルの配置
監視対象の自律稼働システムが出力するログファイルを、`config.json`で指定した`log_directory`（デフォルトは`logs/`）に配置してください。
バリデーターは以下の命名規則のログファイルを想定しています。
-   システムリソース: `system_YYYY-MM-DD.log`
-   エラーイベント: `error_YYYY-MM-DD.log`
-   学習サイクル: `learning_YYYY-MM-DD.log`
-   API使用量: `api_YYYY-MM-DD.log`

### 3. バリデーターの実行
`main.py`スクリプトを実行します。これにより、設定されたすべての検証ステップが実行され、結果がコンソールに出力されます。

```bash
python main.py
```

実行後、最終的な検証レポートがコンソールに表示されます。レポートには各検証カテゴリのステータス（PASS/WARN/FAIL）と詳細が含まれます。

## API仕様
このツール自体はAPIを提供しませんが、以下の内部クラスとメソッドが主要な機能を提供します。

### `AutonomousSystemValidator` (main.py)
-   `__init__(self, config_path="config.json")`: バリデーターを初期化します。
-   `run_validation(self)`: 全ての検証ステップを実行し、レポートを生成します。

### `SystemMetricsCollector` (utils.py)
-   `get_cpu_percent(self, interval=0.1)`: 現在のCPU使用率を返します。
-   `get_memory_info(self)`: 現在のメモリ使用量（合計、使用済み、空きなど）を辞書で返します。
-   `get_disk_info(self, path='/')`: 指定パスのディスク使用量（合計、使用済み、空きなど）を辞書で返します。

### `LogParser` (utils.py)
-   `__init__(self, log_directory)`: ログが格納されているディレクトリを指定してパーサーを初期化します。
-   `find_log_files(self, prefix="")`: 指定されたプレフィックスに一致するログファイルを検索します。
-   `parse_system_metrics_from_logs(self, log_paths)`: システムメトリクスログからCPU、メモリ、ディスク使用量の時系列データを抽出します。
-   `detect_memory_leaks_signatures(self, metrics_data)`: メモリ使用量のログデータから潜在的なメモリリークの兆候を検出します。
-   `parse_error_events_from_logs(self, log_paths)`: エラーログからF7、リトライ、F9イベントなどを抽出します。
-   `parse_learning_events_from_logs(self, log_paths)`: 学習ログからF8トリガー、ナレッジ蓄積、パターン学習イベントを抽出します。
-   `parse_api_usage_from_logs(self, log_paths)`: APIログからClaudeおよびGoogle Sheets APIの使用量データを抽出します。
-   `find_patterns(self, log_paths, patterns)`: 複数のログファイルから特定の正規表現パターンに一致する行を検索します。
-   `check_log_rotation(self, log_directory, prefix, retention_days=7)`: ログローテーションの健全性を確認します。

### `APITracker` (utils.py)
-   `calculate_total_usage(self, api_usage_data, api_name)`: 特定のAPIの総使用量（トークン数、リクエスト数、推定コスト）を計算します。
-   `check_rate_limits(self, usage_data, max_limit, usage_type='tokens')`: API使用量がレート制限内に収まっているかをチェックします。

### `ReportGenerator` (utils.py)
-   `generate_summary(self, validation_results)`: 検証結果の要約レポートを生成します。

## 最終チェックリスト

システムの本番運用を開始する前に、以下の項目を**必ず**確認してください。

### I. 起動前チェック項目

1.  **環境設定の確認**
    *   [ ] 全ての環境変数（APIキー、データベース接続文字列など）が本番環境用に正しく設定されている。
    *   [ ] `config.json`およびその他の設定ファイルが本番環境に合わせた値に更新されている。
    *   [ ] 必要な依存ライブラリ（Pythonパッケージ、システムライブラリ）がすべてインストールされている。
    *   [ ] ネットワーク設定（ファイアウォール、プロキシ、DNS）が外部APIやDBへの接続を許可している。
    *   [ ] 時刻同期（NTP）が正しく設定されており、システム時刻が正確である。

2.  **リソースと容量の確認**
    *   [ ] ディスクの空き容量が十分である（少なくとも今後1ヶ月間のログやデータ増加に対応できる量）。
    *   [ ] システムメモリが十分である。
    *   [ ] CPUリソースがシステムのピーク負荷に対応できる見込みである。
    *   [ ] データベースの空き容量とパフォーマンスが適切に設定されている。

3.  **セキュリティとアクセス制御**
    *   [ ] APIキーや認証情報がハードコードされておらず、安全な方法で管理されている（例: 環境変数、シークレットマネージャー）。
    *   [ ] サービスアカウントやユーザーの権限が最小限に抑えられている。
    *   [ ] 外部への通信がHTTPS/SSLで暗号化されている。
    *   [ ] 不要なポートが閉じられている。

4.  **ログと監視**
    *   [ ] ログディレクトリが存在し、システムが書き込み権限を持っている。
    *   [ ] ログローテーション設定が有効であり、古いログが定期的に削除されるようになっている。
    *   [ ] 監視ツール（Prometheus, Grafanaなど）が正しく設定され、本番システムのメトリクスを収集できるようになっている。
    *   [ ] アラート通知（F9など）の宛先（メールアドレス、Slackチャンネルなど）が正しく設定され、機能することをテスト済みである。

5.  **バックアップとリカバリ**
    *   [ ] 重要なデータ（ナレッジベース、設定、データベース）のバックアップ戦略が確立されている。
    *   [ ] バックアップデータからのリカバリ手順が文書化され、テスト済みである。

### II. 稼働中監視項目

1.  **システムリソースの監視**
    *   [ ] **CPU使用率**: 長期間にわたる高負荷がないか、スパイクがないか。
    *   [ ] **メモリ使用率**: 上昇トレンドがないか（メモリリークの兆候）、逼迫状態がないか。
    *   [ ] **ディスクI/O**: 過剰なディスクI/Oが発生していないか。
    *   [ ] **ディスク空き容量**: 急速な減少がないか、閾値を超えていないか。

2.  **エラーとイベントの監視**
    *   [ ] **エラーログ**: 新しいERRORレベルのログが頻繁に出力されていないか。
    *   [ ] **F7 (自己修復)**: F7アクションがログに記録され、問題解決に寄与しているか。
    *   [ ] **リトライ機構**: エラー時にリトライが適切に行われているか。
    *   [ ] **F9 (人間通知)**: F9が発火すべき状況で通知が正確に送られているか。

3.  **学習サイクルの監視**
    *   [ ] **F8 (自己進化)**: F8トリガーが設定された条件（例: 6時間稼働/50エラー）でログに記録されているか。
    *   [ ] **ナレッジ蓄積**: 新しいナレッジが定期的にログに記録され、蓄積されているか。
    *   [ ] **パターン学習**: 新しいパターンが学習され、その効果がログやメトリクスに現れているか。

4.  **API使用量の監視**
    *   [ ] **Claude API**: トークン消費量が許容範囲内であるか。レート制限に抵触していないか。
    *   [ ] **Google Sheets API**: リクエスト数が許容範囲内であるか。レート制限に抵触していないか。
    *   [ ] APIの応答時間: 外部APIへのリクエストが遅延していないか。

5.  **システム動作の監視**
    *   [ ] **システム応答性**: システムが定期的に処理を実行し、応答が遅延していないか。
    *   [ ] **データ整合性**: 処理されたデータに予期せぬ不整合が発生していないか。
    *   [ ] **ネットワーク接続**: 外部サービスへの接続が安定しているか。

### III. 停止時確認項目

1.  **正常シャットダウンの確認**
    *   [ ] システムが正常なシャットダウン手順を踏んで停止できることを確認。
    *   [ ] シャットダウン時にエラーログが生成されていないか。
    *   [ ] 起動していたプロセスが全て終了していることを確認。

2.  **データ永続性の確認**
    *   [ ] 停止前に重要なデータ（ナレッジベース、中間状態など）が永続ストレージに保存されていることを確認。
    *   [ ] 再起動後にシステムが以前の状態から再開できることを確認（チェックポイント、リカバリ機能のテスト）。

3.  **リソースの解放**
    *   [ ] 停止後に全てのシステムリソース（メモリ、ファイルディスクリプタ、ネットワーク接続）が適切に解放されていることを確認。
    *   [ ] 一時ファイルやキャッシュが適切にクリーンアップされていることを確認。

このチェックリストは、本番運用におけるシステムの健全性を維持し、潜在的な問題を早期に発見するためのガイドラインです。各項目を定期的に確認し、システムの安定稼働を保証してください。
