タイトル: 日付時刻処理のタイムゾーン問題
カテゴリ: データ処理/日付時刻
重要度: 中

【問題】
何が起きた: 異なるタイムゾーン間で日付時刻の不整合が発生
環境: 国際化アプリケーション, 分散システム

【原因分析】
根本原因: タイムゾーンの一貫性のない取り扱い
直接原因: 
1. ナイーブなdatetimeオブジェクトの使用
2. タイムゾーン情報の保存漏れ
3. クライアントとサーバー間のタイムゾーン不一致

【解決策】
解決手法: タイムゾーンを意識した一貫した日付時刻処理
実装例:
from datetime import datetime, timezone
import pytz

# 現在時刻の取得（UTC）
now_utc = datetime.now(timezone.utc)

# 特定のタイムゾーンへの変換
jst = pytz.timezone('Asia/Tokyo')
now_jst = now_utc.astimezone(jst)

# 文字列として保存（ISOフォーマット）
timestamp_str = now_utc.isoformat()

# 文字列からdatetimeへの変換
def parse_iso_timestamp(timestamp_str):
    dt = datetime.fromisoformat(timestamp_str.replace('Z', '+00:00'))
    if dt.tzinfo is None:
        dt = dt.replace(tzinfo=timezone.utc)
    return dt

# データベースでの保存
# 常にUTCで保存し、表示時に変換する

【学び】
1. 内部処理では常にUTCを使用する
2. タイムゾーン情報を保持する
3. 表示時にのみローカルタイムゾーンに変換する
