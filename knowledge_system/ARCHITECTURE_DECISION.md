# 🏗️ アーキテクチャ決定

## 📋 **決定事項**
`knowledge_system` を**スクリプトコレクション**として扱い、Pythonパッケージとしては扱わない

## 🎯 **理由**
1. **複雑性の削減**: パッケージ管理、インポート問題の回避
2. **運用の簡素化**: 個別スクリプトとして実行可能
3. **開発速度の向上**: 循環インポートなどの問題が発生しない

## 🔧 **実装方針**
1. 各スクリプトは独立して動作する
2. 共通機能はユーティリティとして共有
3. 設定は環境変数と設定ファイルで管理
4. データベース接続は各スクリプトで個別に確立

## 📁 **新しい構造**
knowledge_system/
├── database/ # データベースファイル
├── scripts/ # 実行可能スクリプト
│ ├── register.py # 登録スクリプト
│ ├── search.py # 検索スクリプト
│ └── sync.py # 同期スクリプト
├── utils/ # 共通ユーティリティ
│ ├── database.py # データベース操作
│ ├── vectors.py # ベクトル操作
│ └── models.py # モデル管理
└── config/ # 設定ファイル
