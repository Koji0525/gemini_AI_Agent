【ナレッジ登録開始】
タイトル: SafeSheetsWrapper - 実際のAPI仕様に基づく修正
カテゴリ: Python/Google Sheets API/再発防止
重要度: 高

【問題】
何が起きた: SafeSheetsWrapperが存在しないメソッド名(read_range)を呼び出しエラー
環境: Google Sheets API v4, Python 3.8+, GoogleSheetsManager
エラー例: 'GoogleSheetsManager' object has no attribute 'read_range'

【原因分析】
根本原因: API仕様確認なしにメソッド名を推測して実装
直接原因: 
1. GoogleSheetsManagerの実際のメソッド名を確認せずにコード生成
2. 運用ルール13（API使用前の必須確認）を守れていない
3. 新旧のSafeSheetsWrapperが混在

【解決策】
解決手法: API検証ツールで実際のメソッド名を確認後、SafeSheetsWrapperを修正

実装例:
# ✅ STEP 1: API仕様確認（必須）
python3 tools/api_validator.py GoogleSheetsManager

# 確認された実際のメソッド:
# - read_sheet(sheet_name: str) -> List[Dict]
# - get_sheet_data(sheet_name: str) -> List[Dict]
# - write_sheet(sheet_name: str, data: List[List]) -> bool

# ✅ STEP 2: SafeSheetsWrapperを実際のAPIに基づいて実装
from tools.safe_sheets_wrapper import SafeSheetsWrapper
from tools.sheets_manager import GoogleSheetsManager

sheets = GoogleSheetsManager()
safe_sheets = SafeSheetsWrapper(sheets)

# 正しい使い方（実際のAPIを使用）
data = safe_sheets.safe_read('project_goal', default=[])  # read_sheet()を内部で呼び出し

# 互換性メソッド（read_rangeは存在しないが、SafeWrapperが対応）
range_data = safe_sheets.read_range('project_goal!A1:Z10')  # 内部でread_sheet()に変換

# ❌ 避けるべき使い方
sheets.read_range('A1:Z10')  # 存在しないメソッド

【機能一覧】
1. API検証: 初期化時に必須メソッドの存在を確認
2. safe_read: read_sheet()を使用、エラー時はデフォルト値返却
3. read_range: 互換性のため、内部でread_sheet()を呼び出して2次元配列に変換
4. safe_write: write_sheet()を使用、1次元→2次元配列の自動変換
5. safe_append: 既存データを読み取り、新しい行を追加してwrite_sheet()
6. __getattr__: メソッド名の自動修正と類似メソッド提案

【学び】
1. 必ずAPI検証ツールで実際のメソッド名を確認してからコード生成
2. ドキュメントではなく実装（実際のコード）を確認
3. SafeSheetsWrapperで実際のAPIをラップし、互換性を提供
4. 初期化時に_validate_api()で必須メソッドの存在確認
5. エラー時のデフォルト値設定で処理継続

【予防策】
- 新しいクラス使用前に必ずapi_validator.py実行（運用ルール13）
- GoogleSheetsManagerの直接使用を禁止、必ずSafeSheetsWrapper経由
- CI/CDパイプラインにAPI検証を統合
- 月次で重複チェックとAPI仕様の再確認

【横展開】
- 他の外部API（WordPress, Gemini）にも同様のWrapper適用可能
- API検証ツールのパターンは全クラスに適用可能
- safe_read/write/appendパターンは汎用的
