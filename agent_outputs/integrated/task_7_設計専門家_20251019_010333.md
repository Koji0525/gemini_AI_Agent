# タスク 7: 設計専門家

**概要**: 機密情報（価格など）の表示・非表示、ログイン・非ログインユーザーのアクセス制御に関するセキュリティ仕様定義書作成

承知いたしました。設計専門家として、WordPress案件管理システムにおける機密情報のアクセス制御とセキュリティ仕様を定義するレポートを作成します。この仕様は、特にM&A案件における機密性を確保するため、価格情報などのカスタムフィールドデータと、コンテンツ全体へのアクセスを、ユーザーのログイン状態とロールに基づいて厳格に制御することを目的とします。機密情報アクセス制御・セキュリティ仕様定義書1. 概要と基本方針本仕様は、カスタム投稿タイプ ma_deal (M&A案件情報) に含まれる機密情報（特に価格関連）の表示・非表示、および案件コンテンツ全体へのアクセスを、ログイン状態とユーザーロールに基づいて制御する実装を定義します。項目詳細対象コンテンツカスタム投稿タイプ ma_deal機密情報案件の希望価格帯 (price_range)、直近売上高 (seller_latest_sales)、財務ハイライト (seller_financial_summary) など。セキュリティ原則デフォルトですべての機密情報を非表示とし、権限を持つユーザーにのみ表示する。Export to Sheets2. 機密情報（カスタムフィールド）の表示制御仕様機密性の高いカスタムフィールドを特定し、ユーザーのロールに基づき、フロントエンド（案件詳細ページ）での表示・非表示を制御します。2.1. 制御対象カスタムフィールドの定義ACFフィールド名機密レベル制御方針price_range (希望価格帯)高ログインユーザーかつ特定ロールにのみ表示。seller_latest_sales (直近売上高)高ログインユーザーかつ特定ロールにのみ表示。seller_financial_summary (財務ハイライト)最高ログインユーザーかつ特定ロールにのみ表示。seller_company_name (企業名)中ログインユーザーにのみ表示（非ログインには非表示）。Export to Sheets2.2. 制御ロジックの実装方法フロントエンドのテンプレートファイル（例: single-ma_deal.php）内で、以下のロジックを使用して条件分岐を実装します。制御対象ユーザー条件実現方法（WordPress関数）非ログインユーザーすべての非ログインユーザーif ( ! is_user_logged_in() ) { ... }ログインユーザー（一般）subscriber や customer などのロールif ( current_user_can('subscriber') ) { ... }提携パートナーpartner ロールif ( current_user_can('partner') ) { ... }システム管理者administrator ロールif ( current_user_can('administrator') ) { ... }Export to Sheets【実装コード概略】PHP// 例: 希望価格帯の表示制御
if ( current_user_can('partner') || current_user_can('administrator') ) {
    // 提携パートナーまたは管理者であれば表示
    echo '<p>希望価格帯: ' . get_field('price_range') . '</p>';
} else {
    // それ以外のユーザーには表示しない、または代替テキストを表示
    echo '<p>希望価格帯: *ログインおよび権限が必要です*</p>';
}
3. コンテンツ（案件全体）のアクセス制御仕様機密性の高い案件コンテンツ全体へのアクセスを、ログイン状態に基づいて制御します。3.1. 案件全体へのアクセス制御アクセスポイントユーザー条件制御方針実装方法案件詳細ページ (single-ma_deal.php)非ログインユーザー完全にアクセスをブロックし、ログインページへリダイレクト。template_redirect アクションフックを使用し、非ログイン時は wp_redirect( wp_login_url() ) を実行。案件一覧/検索結果 (archive-ma_deal.php)非ログインユーザー案件のリストは表示せず、「ログインが必要です」というメッセージを表示。pre_get_posts フックで非ログイン時はクエリ結果を空にするか、テンプレート内で条件分岐。Export to Sheets3.2. 検索機能への制御項目制御方針備考検索フォームの表示ログインユーザーにのみ表示する。非ログインユーザーは検索自体が不要なため。検索結果の絞り込み検索ロジックはログインを前提とし、非ログインユーザーからの検索リクエストは処理しない。Export to Sheets4. セキュリティ強化対策機密性の高いM&A案件情報を扱うシステムとして、以下のセキュリティ対策を講じます。4.1. データ層の保護 (Database)対策項目仕様目的REST APIの無効化カスタム投稿タイプ ma_deal のREST APIを無効化する。認証されていない外部からのAPI経由のデータ漏洩リスクを排除する。データベース暗号化 (検討)機密性の高いデータ（例：財務情報）をデータベース層で暗号化する。データベースが侵害された場合の情報漏洩リスクを最小化する。（ただし、実装コストは高い）Export to Sheets4.2. ユーザー認証とセッション管理対策項目仕様目的SSL/TLSの強制サイト全体でHTTPS接続を強制する。ログイン情報やデータの通信経路における盗聴を防ぐ。パスワードポリシー強固なパスワードポリシー（文字数、種類）を強制する。ブルートフォースアタック（総当たり攻撃）への耐性を向上させる。Export to Sheets4.3. バックエンドの保護対策項目仕様目的不正アクセス防止4.2. 編集・削除権限の制御で定義した通り、map_meta_cap を使ってURLを直接操作された場合のアクセスを厳格に制御する。認証・認可を経ない不正な情報アクセスを防止する。Export to Sheetsこれらの仕様に基づき、機密情報の表示制御とコンテンツへのアクセス制御を実装することで、M&A案件管理システムに求められる高いセキュリティ水準を達成します。
