# タスク 4: design

**概要**: WordPressにおける検索機能の具体的な実装仕様定義書作成（カスタムタクソノミー/カスタムフィールド検索の設計、検索対象項目、価格帯レンジ検索の実現方法）

---

ご依頼ありがとうございます。デザインの専門家として、ユーザーエクスペリエンス（UX）を考慮したWordPress検索機能の実装仕様定義書を作成します。特に、複雑なM&A案件情報に必須となるカスタムタクソノミー、カスタムフィールド、価格帯レンジ検索に焦点を当てます。WordPress検索機能 実装仕様定義書（M&A案件情報向け）1. 目的と検索UXの定義本検索機能の目的は、買い手候補者が膨大な案件情報の中から、カスタム投稿タイプ（deal）に登録された情報を、複数の条件（カテゴリ、価格、企業属性）で効率よく絞り込めるようにすることです。目標とするUX: 複数の条件を組み合わせた**ファセット検索（絞り込み検索）**を可能とし、検索結果がリアルタイムに近い速度で更新されること。2. 検索対象とするCPTと項目CPT/タクソノミー検索対象項目検索種別実装方法案件情報 (deal)タイトル、案件サマリー (summary)キーワード検索 (部分一致)標準WP検索、または全文検索プラグイン産業カテゴリ (industry)ターム名絞り込み検索 (複数選択可)カスタムタクソノミー検索 (tax_query)案件種別 (deal_type)ターム名絞り込み検索 (複数選択可)カスタムタクソノミー検索 (tax_query)希望売却価格 (asking_price)数値データレンジ検索 (以上/以下)カスタムフィールド検索 (meta_query)募集状況 (status)フィールド値絞り込み検索 (単一選択)カスタムフィールド検索 (meta_query)所在地 (location)フィールド値絞り込み検索 (複数選択可)カスタムフィールド検索 (meta_query)Export to Sheets3. 実装の具体的な設計仕様WordPressの標準的な WP_Query を拡張する形で実装します。3.1. カスタムタクソノミー検索の設計対象: industry（産業カテゴリ）、deal_type（案件種別）技術仕様: WP_Query の tax_query パラメータを使用します。仕様詳細:ユーザーが複数のタクソノミータームを選択した場合、それらのタームはOR条件で結合されます（例：「IT」または「製造業」の案件）。ただし、複数の異なるタクソノミー（例：industryとdeal_type）の条件が同時に指定された場合は、タクソノミーグループ間はAND条件で結合されます。// tax_query の構造例
'tax_query' => array(
    'relation' => 'AND', // 異なるタクソノミー間はAND
    array(
        'taxonomy' => 'industry',
        'field'    => 'slug',
        'terms'    => array('it', 'manufacturing'), // OR結合
        'operator' => 'IN'
    ),
    array(
        'taxonomy' => 'deal_type',
        'field'    => 'slug',
        'terms'    => array('stock-transfer'), // OR結合
        'operator' => 'IN'
    )
)
3.2. カスタムフィールド（メタデータ）検索の設計対象: status（募集状況）、location（所在地）技術仕様: WP_Query の meta_query パラメータを使用します。status (募集状況) 検索:フィールドキー: status仕様: ユーザーが選択した値と完全に一致する案件を抽出します。location (所在地) 検索:フィールドキー: location仕様: ユーザーが選択した都道府県名（または地域名）を LIKE 演算子、または完全一致で検索します。複数選択は OR 結合とします。3.3. 価格帯レンジ検索 (asking_price) の実現方法価格 (asking_price) は数値カスタムフィールドとして登録されています。これを範囲で検索します。技術仕様: meta_query を使用し、BETWEEN 比較演算子、または >= / <= 比較演算子を組み合わせて実現します。実装例 (ユーザーが「1億円〜3億円」を選択した場合):フロントエンドでレンジの最小値 (10000) と最大値 (30000) を取得します。meta_query で以下の条件を設定します。// meta_query の構造例
'meta_query' => array(
    array(
        'key'     => 'asking_price',
        'value'   => array(10000, 30000), // 単位は万円
        'type'    => 'NUMERIC', // 数値として比較
        'compare' => 'BETWEEN'
    )
)
柔軟性の確保: 最小値のみ、または最大値のみが指定された場合は、>= または <= 演算子を使用するようにロジックを分岐させます。4. 検索パフォーマンスへの配慮複雑なカスタムフィールドやタクソノミー検索を多用する場合、WordPress標準のWP_Queryだけではパフォーマンスが低下する可能性があります。推奨対策:インデックスの適用: ACFのカスタムフィールド (asking_price, statusなど) に対して、データベースレベルでインデックスを設定します。プラグインの活用: ElasticsearchやAlgoliaなどの外部検索エンジン、またはRelevanssiなどの高性能検索プラグインの導入を検討します。これにより、大規模なデータ量にも対応できる高速なファセット検索を実現します。5. デザイン・UIへの指示（UXの視点）検索フォームの配置: 検索フォームは、案件一覧ページのサイドバーまたは画面上部に固定し、ユーザーが常に条件を変更できるようにします。非同期通信 (Ajax): 検索ボタンを押さずに、チェックボックスやレンジスライダーを操作した瞬間にAjax通信で検索結果を更新し、ロード中のインジケーターを表示することで、快適なUXを提供します。アクティブな条件表示: 現在適用されている検索条件を分かりやすい位置（例: 検索結果の上部）に表示し、ワンクリックで解除できるようにします。
