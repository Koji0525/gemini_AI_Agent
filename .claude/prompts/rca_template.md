# 根本原因分析（RCA）テンプレート（R008, R009）

## R008: 問題長期化時の対応

同じエラーが2-3回発生した場合、以下を実行:

### ステップ1: 原因候補10個以上列挙
```
原因候補（14個）:
1. ❌ <可能性のある原因1>
2. ❌ <可能性のある原因2>
3. ❌ <可能性のある原因3>
...
14. ❌ <可能性のある原因14>
```

### ステップ2: 切り分け
```bash
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
# 1. 最も可能性の高い原因を確認
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

<確認コマンド>

# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
# 2. 次の候補を確認
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

<確認コマンド>
```

### ステップ3: 抜本的対策
```
抜本的対策:
- 一時的な修正ではなく根本解決
- 類似エラーも同時に防止
- 自動化・ツール化を検討
```

## R009: 解決後のなぜなぜ分析

### 5段階のなぜ分析
```
❓ なぜ1: <表面的な問題>
└─ <直接的な原因>

❓ なぜ2: <なぜ直接的な原因が発生?>
└─ <背景にある問題>

❓ なぜ3: <なぜ背景の問題が発生?>
└─ <プロセスの問題>

❓ なぜ4: <なぜプロセスに問題?>
└─ <仕組みの不備>

❓ なぜ5: <なぜ仕組みが不備?>
└─ <根本原因>
```

### 再発防止策
```
🛡️ 再発防止策（即実装可能）:

対策1: <具体的な対策>
対策2: <具体的な対策>
対策3: <具体的な対策>
```

### 仕組み化の検討
```
🔄 仕組み化:

1. ツール化
   → <自動化ツールの提案>

2. チェックリスト
   → <確認項目の標準化>

3. プレコミットフック
   → <自動チェックの提案>
```

## 実例

### 問題: get_pending_tasks で tasks 未定義エラー

#### R008適用: 原因候補14個
```
1. ❌ tasks = [] の初期化忘れ
2. ❌ raise Exception削除で前後のコードが露出
3. ❌ インデント崩れ
...
14. ❌ 複数回の編集で矛盾が蓄積
```

#### R009適用: なぜなぜ分析
```
❓ なぜ1: デバッグに長時間かかった
└─ エラーの根本原因が見えなかった

❓ なぜ2: 根本原因が見えなかった
└─ エラーメッセージが誤解を招いた

❓ なぜ3: エラーメッセージが誤解を招いた
└─ デバッグコードが本番に残っていた

❓ なぜ4: デバッグコードが残っていた
└─ 部分的な修正を繰り返した

❓ なぜ5: 部分的修正を繰り返した
└─ テスト不足 & コードレビュー不足
```

#### 再発防止策
```
1. 修正前の自動バックアップ（→ file_version_manager）
2. 単体テスト生成ツール（→ generate_unit_test.py）
3. エラーメッセージチェック（→ check_error_messages.py）
```
