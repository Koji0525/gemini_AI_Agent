【問題】
何が起きた: RAGエンジンがナレッジを98件しか読めず、24時間稼働システムが未完成
環境: Python 3.8+, asyncio, RAG v2, GoogleSheetsManager, SafeSheetsWrapper

【原因分析】
根本原因: rag_engine_local.pyとナレッジファイル形式の不一致
直接原因: 
1. rag_engine_local.py が辞書形式 {"knowledge_base": [...]} を期待
2. 実際のファイルはリスト形式 [...]
3. AttributeError: 'list' object has no attribute 'get'
4. エラーで途中終了 → 98件のみ読み込み

【解決策】
狙い（解決策）: リスト・辞書両対応のナレッジ読み込み、統合形式への変換

実装例:
# ✅ 修正前（エラー発生）
with open(filepath, 'r') as f:
    data = json.load(f)  # リスト形式
    self.rag_engine.load_knowledge([filepath])
    # → data.get("knowledge_base") でエラー

# ✅ 修正後（両対応）
all_knowledge = []
for filepath in knowledge_files:
    with open(filepath, 'r') as f:
        data = json.load(f)
        
        if isinstance(data, list):
            all_knowledge.extend(data)
        elif isinstance(data, dict):
            if 'knowledge_base' in data:
                all_knowledge.extend(data['knowledge_base'])

# 辞書形式で統合して保存
merged_data = {"knowledge_base": all_knowledge}
with open(temp_file, 'w') as f:
    json.dump(merged_data, f)

self.rag_engine.load_knowledge([temp_file])
# → 159件すべて読み込み成功！

【学び】
1. ファイル形式の不一致は isinstance() で確認
2. エラーメッセージ（'list' object has no attribute 'get'）から原因を特定
3. 統合時は両形式に対応するロバストな実装が必要
4. ナレッジ件数の変化（98→159件）で問題検出
5. RAGエンジンの期待形式を事前に確認（運用ルール13）
