# Phase 5 スクリプト3完了: 全システム依存関係可視化

## 何を実装したか
プロジェクト全体（.py、.sh、.md等）の依存関係をD3.jsで可視化するシステム

## 実装成果
- ✅ DependencyAnalyzer実装（AST + 正規表現で依存関係解析）
- ✅ Flask APIエンドポイント追加（/api/dependencies/scan）
- ✅ D3.jsネットワークグラフ実装
- ✅ ファイル影響範囲分析機能
- ✅ Top 10ファイル表示
- ✅ カテゴリ別色分け表示

## 主要機能

### 1. 依存関係解析エンジン
- Pythonファイル: AST解析でimport文抽出
- シェルスクリプト: 正規表現でpython3/bashコマンド抽出
- 全プロジェクトファイルスキャン（__pycache__等は除外）

### 2. ネットワークグラフ可視化
- D3.js Force Layoutでインタラクティブな表示
- ノードサイズ: 被インポート数に比例
- ノード色: カテゴリ別（agent/tool/test/script/doc/other）
- ドラッグ&ドロップ対応

### 3. 影響範囲分析
- ファイルクリックで影響範囲を表示
- 直接影響と間接影響の区別
- 再帰的な依存関係追跡

### 4. 統計情報
- 総ファイル数、依存関係数
- ファイルタイプ別集計
- Top 10表示（最も多くインポートされている/している）

## 解決した課題

### 課題1: ファイル間のつながりが不明
**解決**: ネットワークグラフで一目で把握可能に

### 課題2: 変更時の影響範囲が分からない
**解決**: クリックで影響を受けるファイル一覧を表示

### 課題3: 重複開発や未使用ファイルの検出困難
**解決**: 被インポート数0のファイルが一目で分かる

### 課題4: 汎用的なツールが埋もれている
**解決**: Top 10表示で再利用可能なファイルを発見

## 重要な知見

### D3.js Force Layoutの活用
- `forceSimulation()`: ノード配置の物理シミュレーション
- `forceLink()`: エッジによる引力
- `forceManyBody()`: ノード間の反発力
- `forceCenter()`: 中心への引力

### ASTによる依存関係解析
```python

for node in ast.walk(tree):
    if isinstance(node, ast.Import):
        # import module
    elif isinstance(node, ast.ImportFrom):
        # from module import ...
```
