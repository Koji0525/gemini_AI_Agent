## ✅ 最終的な解決策

### 解決策1: グローバル変数の正しい定義
```python
# api_server.py の先頭（importセクションの後）

# グラフデータをメモリに保持
graph_data = None
```

### 解決策2: 絶対パスでのファイル読み込み
```python
def load_graph_data():
    global graph_data
    
    # 現在のファイル(__file__)から相対パスを計算
    current_dir = Path(__file__).parent
    project_root = current_dir.parent.parent.parent
    graph_file = project_root / "docs" / "dependency_map.json"
    
    # 読み込み処理...
```

### 解決策3: データ再読み込みロジック
```python
@app.get("/api/dependencies")
async def get_dependencies():
    global graph_data
    
    # 1. Noneの場合は読み込み
    if graph_data is None:
        load_graph_data()
    
    # 2. 空配列の場合も再読み込み
    if graph_data is None or len(graph_data.get("nodes", [])) == 0:
        load_graph_data()
    
    # 3. それでも空ならエラー
    if graph_data is None or len(graph_data.get("nodes", [])) == 0:
        return {"nodes": [], "edges": [], "metadata": {"error": "No data"}}
    
    return graph_data
```

## 📚 得られた教訓

### 教訓1: ファイルパスは絶対パス基準で
```
✅ 良い例:
Path(__file__).parent.parent / "docs" / "file.json"

❌ 悪い例:
"docs/file.json"  # カレントディレクトリ依存
```

### 教訓2: グローバル変数は明示的に
```
✅ 良い例:
# ファイル先頭で定義
graph_data = None

def load_data():
    global graph_data  # 明示的に宣言
    graph_data = {...}

❌ 悪い例:
# 定義なし
def load_data():
    graph_data = {...}  # ローカル変数になってしまう
```

### 教訓3: データ読み込みは冗長性を持たせる
```
✅ 良い例:
- 起動時に読み込み
- API呼び出し時にチェック
- 空なら再読み込み
- エラーハンドリング

❌ 悪い例:
- 起動時のみ読み込み
- 失敗したら諦める
```
