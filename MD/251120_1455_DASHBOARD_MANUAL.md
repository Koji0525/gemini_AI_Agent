## ダッシュボードとは

### 概要
ダッシュボードは24時間自律開発システムの**監視・制御インターフェース**です。

**主な機能**：
1. 📊 システム状態の監視
2. 🎮 システムの起動・停止制御
3. 💬 人間からの指示入力（F9）
4. 📋 タスク一覧の表示
5. 📝 リアルタイムログの表示

### アクセス方法
```
http://localhost:8000
```

---

## 起動ボタンの動作

### ▶️ 開始ボタンを押すと何が起きる？
```
【開始ボタンを押す】
    ↓
【24時間稼働システムが起動】
    ↓
【15分サイクルで自動実行開始】
    ├─ F9指示をチェック（human_instructions）
    ├─ F1: ゴールからタスクを自動生成
    ├─ F2: pendingタスクを自動実行 ★
    ├─ F3: 品質を自動評価
    ├─ F6: 品質不合格なら追加タスク生成
    └─ F7: エラーなら自己修復
    ↓
【15分後、再び同じサイクル】
```

### つまり...

**開始ボタン = 24時間自律システムの起動**

起動すると：
- ✅ **pendingタスクを自動実行**
- ✅ **15分ごとに繰り返し**
- ✅ **人間の指示も自動処理**
- ✅ **エラーは自動修復**

### ⏸️ 一時停止ボタン

システムを一時的に停止します。
- 現在実行中のタスクは完了
- 次のサイクルは開始しない
- データは保持される

```

4. pm_tasksシートにタスクとして追加
   ↓
5. 通常のタスクとして実行される
```

## F9人間指示の詳細

### 指示タイプ一覧

#### 1. 📝 タスク追加（最もよく使う）

**用途**: 新しいタスクをシステムに追加

**例**:
```
指示タイプ: タスク追加
内容: データベース最適化を実装してください
優先度: 高
```

**結果**:
- pm_tasksシートに新しいタスクが追加される
- タスクID: human_req_251120_HHMMSS
- 次のサイクルで自動実行される

---

#### 2. ⏸️ システム一時停止

**用途**: システムを一時的に止める

**例**:
```
指示タイプ: システム一時停止
内容: メンテナンス作業のため一時停止
優先度: 高
```

**結果**:
- `/tmp/system_paused.flag` が作成される
- 次のサイクルで停止状態になる
- タスク実行は行われない

---

#### 3. ▶️ システム再開

**用途**: 一時停止を解除

**例**:
```
指示タイプ: システム再開
内容: メンテナンス完了、再開します
優先度: 高
```

**結果**:
- `/tmp/system_paused.flag` が削除される
- 次のサイクルから再開

---

#### 4. 💬 メッセージ（記録用）

**用途**: システムに記録を残す、他の人へのメモ

**例**:
```
指示タイプ: メッセージ
内容: 本日のテストは順調に進行中
優先度: 低
```

**結果**:
- ログに記録される
- タスクは追加されない
- 他の開発者が後で確認できる

**メッセージの使い道**:
1. **システムへの記録**
   - 「データベース接続エラーが発生、手動で修正しました」
   - 「新しい機能のテストを開始」

2. **他の開発者へのメモ**
   - 「明日の朝まで重いタスクを実行予定」
   - 「API制限に注意してください」

3. **進捗メモ**
   - 「Phase 1 完了、次はPhase 2へ」

---

#### 5. 🔄 優先度変更（現在未実装）

**用途**: 既存タスクの優先度を変更

**例**:
```
指示タイプ: 優先度変更
対象タスク: 7_xxx
内容: このタスクを最優先で実行
優先度: 高
```

---

#### 6. ⏹️ タスク停止（現在未実装）

**用途**: 実行中のタスクを停止

---

#### 7. 🚨 緊急停止

**用途**: システムを即座に停止

**例**:
```
指示タイプ: 緊急停止
内容: 重大なエラー発生、すぐ停止
優先度: 高
```

## システムの動作フロー

### 全体の流れ
```
┌─────────────────────────────────────────────┐
│ 1. ユーザーがダッシュボードで指示を入力    │
└─────────────┬───────────────────────────────┘
              ↓
┌─────────────────────────────────────────────┐
│ 2. human_instructionsシートに保存           │
└─────────────┬───────────────────────────────┘
              ↓
┌─────────────────────────────────────────────┐
│ 3. 次のサイクル（最大15分）                 │
│    F9が指示をチェック                       │
└─────────────┬───────────────────────────────┘
              ↓
┌─────────────────────────────────────────────┐
│ 4. process_instructions()で処理             │
│    add_task → pm_tasksに追加                │
│    pause_system → フラグ作成                │
│    message → ログ記録                       │
└─────────────┬───────────────────────────────┘
              ↓
┌─────────────────────────────────────────────┐
│ 5. タスクが通常フローで実行                 │
│    F2: タスク自律実行                       │
│    F3: 品質評価                             │
│    F6: 必要に応じて追加タスク               │
└─────────────┬───────────────────────────────┘
              ↓
┌─────────────────────────────────────────────┐
│ 6. 成果物が生成される                       │
│    agent_outputs/implementation/            │
│    agent_outputs/auto_logs/                 │
└─────────────────────────────────────────────┘
```

## よくある質問

### Q1: 開始ボタンを押さないとタスクは実行されない？

**A**: はい、開始ボタンで24時間稼働システムが起動します。
起動すると、15分ごとに自動的にpendingタスクを実行します。

---

### Q2: 指示を送信してもすぐ実行されない？

**A**: 最大15分かかります。
システムは15分サイクルで動作しているためです。

**すぐに実行したい場合**:
```bash
# 手動で指示を処理
bash sh/process_f9_instructions_now.sh
```

---

### Q3: メッセージタイプはいつ使う？

**A**: 以下の場合に便利です：
- システムの状態を記録
- 他の開発者へのメモ
- 作業ログの記録
- トラブルシューティングの記録

---

### Q4: タスクの実行結果はどこで見る？

**A**: 
```bash
# コマンドで確認
bash sh/show_task_outputs.sh

# または直接
ls -lt agent_outputs/implementation/
```

## まとめ

### ダッシュボードの役割
```
ダッシュボード = システムの司令塔

監視 ━━━ システム状態を常時表示
制御 ━━━ 開始/停止ボタンで制御
指示 ━━━ タスク追加など人間からの指示
確認 ━━━ ログ・タスク一覧を表示
```

### 基本的な使い方

1. **http://localhost:8000 を開く**
2. **▶️ 開始ボタンでシステム起動**
3. **人間指示でタスク追加**
4. **ログで進捗確認**
5. **⏸️ 一時停止で停止**

### キーポイント

- ✅ 開始ボタン = 24時間稼働開始
- ✅ タスク追加 = 最もよく使う機能
- ✅ メッセージ = 記録用
- ✅ 15分サイクル = 自動処理
- ✅ 10秒更新 = リアルタイム監視
