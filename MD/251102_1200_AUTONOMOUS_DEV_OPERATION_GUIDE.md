## システム概要

### 🎯 できること

✅ **目標から自動開発**
- GitHub Actionsで目標を入力
- PM Agentが自動でタスク分解
- Task Executorが順次実行
- WordPress開発も完全自動化

✅ **24時間自律稼働**
- 6時間ごとに自動実行（Cron）
- エラーは自己修復機能で自動対応
- 人間の介入なしに開発継続

✅ **進捗の可視化**
- スプレッドシートでリアルタイム確認
- タスク状態（pending/in_progress/completed）
- 進捗率（0-100%）

✅ **自己学習機能**
- 成功/失敗パターンを自動蓄積
- ナレッジベースで修正レシピ管理
- 実行を重ねるほど精度向上

## 開発を開始する

### 方法1: GitHub Actionsから手動開始（推奨）

1. **GitHubリポジトリを開く**
```
   https://github.com/<your-username>/<your-repo>/actions
```

2. **ワークフローを選択**
   - 左サイドバーから「24時間自律開発システム」を選択

3. **Run workflowをクリック**
   - 右上の「Run workflow」ボタンをクリック

4. **目標を入力**
```
   例: M&Aポータルの検索機能実装
   例: WordPressカスタム投稿タイプ「案件」を作成
   例: Gemini APIを使った記事生成機能の追加
```

5. **優先度を選択**
   - `high`: 最優先で実行
   - `medium`: 通常優先度
   - `low`: 余裕がある時に実行

6. **実行開始**
   - 「Run workflow」を再度クリック
   - システムが自動で開発を開始します

### 方法2: 自動継続実行（Cron）

- **設定不要**: 6時間ごとに自動実行
- **条件**: `pm_tasks`に保留中のタスクがある場合のみ
- **実行時刻**: 0:00, 6:00, 12:00, 18:00 (JST)

## 進捗を確認する

### スプレッドシートで確認

1. **スプレッドシートを開く**
   - Google Sheetsで共有されているスプレッドシートを開く

2. **各シートの役割**

| シート名 | 役割 | 確認すべき情報 |
|---------|------|--------------|
| `project_goal` | 目標管理 | 目標の状態（active/completed） |
| `pm_tasks` | タスク管理 | タスクの状態（pending/in_progress/completed/failed） |
| `task_execution_log` | 実行ログ | 各タスクの実行結果と品質スコア |
| `progress_dashboard` | 進捗ダッシュボード | 全体の進捗率とボトルネック |
| `error_analysis` | エラーログ | エラー発生履歴と修復状況 |

3. **タスク状態の意味**
   - `pending`: 実行待ち
   - `in_progress`: 実行中
   - `completed`: 完了
   - `failed`: 失敗（自動リトライ済み）

### GitHub Actionsで確認

1. **Actionsタブを開く**
2. **実行履歴を確認**
   - 各実行の成功/失敗
   - 実行時間
   - ログ詳細

## 開発を制御する

### GitHub Issuesでコマンド送信

システムは将来的にGitHub Issuesを監視してコマンドを受け付けます（Phase 10で実装予定）。

**予定されているコマンド:**
```
@bot stop          - システムを一時停止
@bot resume        - システムを再開
@bot status        - 現在の進捗を確認
@bot backup-now    - 即座にバックアップ
@bot priority <task_id> high  - タスクの優先度変更
```

### スプレッドシートで直接制御

**緊急停止:**
1. `setting`シートを開く
2. `system_enabled`フラグを`false`に変更

**タスク優先度変更:**
1. `pm_tasks`シートでタスクを探す
2. `priority`列を変更（high/medium/low）

**タスクの手動完了:**
1. `pm_tasks`シートでタスクを探す
2. `status`列を`completed`に変更

## トラブルシューティング

### ❌ システムが動作しない

**確認事項:**
1. GitHub Secretsが正しく設定されているか
   - `GOOGLE_CREDENTIALS`
   - `SPREADSHEET_ID`
2. サービスアカウントにスプレッドシートの編集権限があるか
3. `setting`シートの`system_enabled`が`true`か

**対処法:**
```bash
# ローカルでテスト実行
python3 scripts/integrated_orchestrator_v05_final.py
```

### ⚠️ タスクが失敗し続ける

**確認事項:**
1. `error_analysis`シートでエラー内容を確認
2. 自己修復機能が動作しているか（ログに`🛡️`マークがあるか）

**対処法:**
1. エラー内容に基づいて手動修正
2. `knowledge_base`シートに修正レシピを追加
3. タスクのstatusを`pending`に戻して再実行

### 🔧 開発環境の問題

**WordPress接続エラー:**
- `.env`ファイルのWordPress認証情報を確認
- WP-REST APIが有効か確認

**Google Sheets接続エラー:**
- サービスアカウントファイルの有効期限確認
- スプレッドシートIDが正しいか確認
